CloseProof for Jira

Evidence-checked month-end close for finance teams, inside Jira. See which account reconciliations are really done, and which only look done.

What CloseProof checks

Every account reconciliation is checked by seven deterministic controls each time you open the close. The Rovo agent explains the results; it never decides them.

IDControlRaised when
C1Tie-outGL balance − source balance − reconciling items is not exactly zero. A blocker above the materiality threshold, a warning below it.
C2Roll-forwardThe prior period for the same account is not reviewed, or this period's opening balance differs from the prior period's reviewed closing balance.
C3Segregation of dutiesThe same person prepared and reviewed, the review has no preparer sign-off, or the review is dated before the preparation.
C4Evidence presentNo supporting document is attached.
C5Evidence intactAn evidence file was deleted from the issue, replaced by a different file with the same name, or its SHA-256 no longer matches the hash taken when it was attached.
C6Changed after sign-offBalances, items or evidence changed after the preparer or reviewer signed.
C7Stale itemsA reconciling item is older than the stale-item limit (default 60 days) at the end of the period.

Quick start with the demo

  1. Open a Jira project where you can create and edit issues.
  2. In the project sidebar, open Month-end close (under Apps).
  3. Click Load demo close (click it again any time to rebuild the demo). CloseProof creates eight reconciliation issues for last month, each with a small CSV statement attached, and plants one problem per control.
  4. Read the exceptions in the table. Click Verify evidence to re-download every evidence file and compare its SHA-256 with the hash stored at attach time.
  5. Open one of the issues and expand the Reconciliation panel (issue view, app actions) to see balances, evidence, sign-offs and history.

The demo uses fictional people (for example "Dana Preparer"), so you can see the segregation-of-duties control without a second Jira user.

Working on a real close

1. Create a reconciliation

Create one Jira issue per account (for example "1010 Operating bank account, October"). In its Reconciliation panel, enter the period (YYYY-MM), account code and name, then the balances:

  • GL balance: the general ledger closing balance.
  • Source balance: the independent balance, such as the bank statement or a sub-ledger.
  • Opening (last month close): optional; when set, C2 compares it with last month's reviewed closing balance.
  • Reconciling items: timing differences and other explained items, each with an amount and the date it was opened.

Amounts are stored as exact integers in minor units, so 0.01 differences are never lost to rounding.

2. Attach evidence

Attach the statement or schedule to the Jira issue as usual, then pick it in the panel's Evidence section. CloseProof downloads the file once and stores its SHA-256 fingerprint. If anyone later deletes, replaces or edits the file, C5 flags it.

3. Sign off

The preparer signs when C1, C2, C4 and C5 have no blockers. A different person then signs as reviewer. Each sign-off stores a hash of the reconciliation's content; if anything changes afterwards, C6 asks for a new sign-off. Use Reopen to withdraw sign-offs and rework a reconciliation. Every action is kept in the History section.

4. Close the period

When every reconciliation is reviewed with no blockers or warnings, the dashboard enables Issue close certificate. The certificate is a single SHA-256 over every reviewed reconciliation of the period. If a reviewed reconciliation changes later, the dashboard shows that the certificate is no longer valid.

Settings

Each project has its own currency code (default USD), materiality threshold (default 100.00) and stale-item limit (default 60 days).

Close Controller agent (Rovo)

If your site has Rovo, open Rovo chat and pick Close Controller. Try:

  • What is blocking this month's close?
  • Explain the exceptions on FIN-3
  • Draft the close memo for the controller

The agent calls four read-only actions (get close status, list close exceptions, explain reconciliation, draft close memo). It cannot sign, edit or delete anything, and it only sees projects you can browse.

MCP tools

The same four read-only tools are exposed through Atlassian's MCP server as CloseProof, so an MCP client connected to your Atlassian site can ask for close status or exceptions. An administrator must allow the app's tools to be exposed. See skill.md for how an agent should use them.

Permissions

All Jira calls run as the signed-in user. Reading the close requires Browse projects; editing, signing, loading the demo and issuing certificates require Edit issues in that project.
